## Purpose

定义应用级暗黑模式能力，包括默认跟随系统、用户主题偏好、持久化、生效一致性，以及 View/Compose/自定义 View 的可读性要求。

## Requirements

### Requirement: 默认跟随系统主题
当没有保存用户显式主题偏好时，应用 SHALL 默认跟随 Android 系统的浅色或暗色主题。

#### Scenario: 系统暗色主题已启用
- **WHEN** 应用启动时没有保存的主题偏好，且设备正在使用暗色主题
- **THEN** 应用页面使用暗色背景、暗色表面和清晰可读的前景色

#### Scenario: 系统浅色主题已启用
- **WHEN** 应用启动时没有保存的主题偏好，且设备正在使用浅色主题
- **THEN** 应用页面使用浅色背景、浅色表面和清晰可读的前景色

### Requirement: 用户主题偏好
应用 SHALL 在提供主题设置的位置允许用户选择跟随系统、浅色和暗色三种主题模式。

#### Scenario: 用户选择暗色主题
- **WHEN** 用户选择暗色主题
- **THEN** 无论当前系统主题如何，应用都应用暗色模式

#### Scenario: 用户选择浅色主题
- **WHEN** 用户选择浅色主题
- **THEN** 无论当前系统主题如何，应用都应用浅色模式

#### Scenario: 用户选择跟随系统
- **WHEN** 用户选择跟随系统
- **THEN** 应用使用当前 Android 系统主题

### Requirement: 持久化主题模式
应用 SHALL 持久化用户选择的主题模式，并在后续启动时、页面渲染主要内容前重新应用该模式。

#### Scenario: 显式选择暗色后重新启动
- **WHEN** 用户此前选择了暗色主题并重新启动应用
- **THEN** 应用以暗色模式启动，且不要求用户重新选择偏好

### Requirement: 主题感知的 View 资源
XML 布局和 drawable 资源 SHALL 为暗色模式下必须可读的表面、文字、分割线和控件使用主题感知颜色或夜间专用资源。

#### Scenario: 暗色模式下展示 View 页面
- **WHEN** 基于 View 的 Activity、弹窗或底部面板在暗色模式下展示
- **THEN** 其背景、文字、控件和关键容器具有足够对比度，不依赖浅色专用白色表面或黑色文字

### Requirement: Compose 与 View 模式一致
对于同一个用户主题偏好，Compose 页面和基于 View 的页面 SHALL 使用相同的最终生效主题模式。

#### Scenario: 暗色覆盖后的混合 UI
- **WHEN** 用户选择暗色主题，并在 Compose 页面和 XML 页面之间导航
- **THEN** 两套 UI 都以暗色模式渲染

### Requirement: 自定义 View 颜色兼容
当颜色影响可读性时，自定义 View 和代码中的 UI 颜色赋值 SHALL 从资源或主题属性解析主题敏感颜色。

#### Scenario: 暗色模式下展示自定义 View
- **WHEN** 自定义 View 或 adapter 渲染的条目在暗色模式下展示
- **THEN** 文字、连接线、背景和交互状态在当前主题下保持可见
